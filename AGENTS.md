# AGENTS.md

Guidance for AI coding agents (and new team members) working in this repository. Read this
first; see [TESTING.md](TESTING.md) for how to verify changes and [PLANS.md](PLANS.md) for what is
being worked on and why.

## What this project is

A local, privacy-focused document workspace: import PDF/Word/PowerPoint/Excel/CSV/HTML/text,
convert to Markdown with locators (`Page 3`, `Slide 2`, `Sheet: Sites`), ask a **local** LLM
(llama.cpp `llama-server`) about them with verified citations, and export Word/Excel/PowerPoint/PDF.
English and Finnish are first-class languages. Accuracy is measured with the project's own
benchmark (`benchmark/`).

## Non-negotiable rules

1. **Local only.** The application must never send document content off the machine. All LLM
   traffic goes through `backend/app/services/llm/client.py` to a localhost endpoint; the privacy
   policy (`services/privacy/policy.py`) blocks anything else. Never add a cloud AI call, telemetry
   or analytics to the app. The only exception is the **benchmark-only** frontier comparison
   (`services/evaluation/frontier.py`, Claude and GPT reference models), which sends nothing but the
   fictional benchmark corpus, runs only from `benchmark/run.py --provider claude|openai`, and is
   never imported by the app's routers (a test enforces this).
2. **The AI proposes, the app verifies.** Model output that drives an action is schema-constrained
   JSON validated with Pydantic (`services/features/structured.py`); numbers are computed by code,
   not by the model (`data_query.py`); citations are resolved against real sections
   (`citations.py`). Keep this pattern for new features.
3. **No machine-specific paths in the repo.** Paths to `llama-server` and models live in the
   git-ignored `data/llm_settings.json`, entered through the Model launcher.
4. **Never silently truncate documents.** If a prompt does not fit the context window, raise
   `ContextTooLarge` with the numbers (`context_budget.py`).
5. **Every behaviour change needs a test**, and every change to prompts, retrieval or scoring needs
   a benchmark re-run (see TESTING.md). Do not tune the benchmark's expected answers to make a model
   pass.

## Repository map

| Path | What lives there |
| --- | --- |
| `backend/app/routers/` | FastAPI endpoints (thin: validate, call a service, map errors) |
| `backend/app/services/parsers/` | one parser per input format -> `DocumentContent` |
| `backend/app/services/llm/` | llama-server client, prompts, context strategies, token budget, launcher |
| `backend/app/services/retrieval/` | locator-preserving chunker, BM25 with English/Finnish stemming |
| `backend/app/services/features/` | citations, fact-check, study, data query, privacy guard, translate |
| `backend/app/services/evaluation/` | benchmark: suite loader, scoring, runner, report, frontier reference |
| `backend/app/services/writers/` | DOCX / XLSX / PPTX / PDF / LaTeX / CSV writers |
| `backend/tests/` | pytest suite (fixtures generated by `make_fixtures.py`) |
| `frontend/src/components/` | React panels, one per tab (`ChatPanel`, `EvaluationPanel`, ...) |
| `frontend/src/services/api.ts`, `types/api.ts` | typed API client; keep in sync with the backend schemas |
| `benchmark/` | bilingual corpus, `make_questions.py` (source of the questions), results, `run.py` CLI |
| `scripts/` | start scripts and the llama-server guide |

```powershell
# backend (from backend/)
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
.venv\Scripts\python -m pytest -q

# frontend (from frontend/)
npm install
npm run dev        # http://127.0.0.1:5173
npm run build      # type-check + build
npm run lint

# benchmark (from the repository root)
backend\.venv\Scripts\python benchmark\run.py check       # suite self-check, no model
backend\.venv\Scripts\python benchmark\run.py retrieval   # retrieval recall, no model
backend\.venv\Scripts\python benchmark\run.py run --quick # needs a running llama-server
```

## Conventions

- Python 3.11+ (developed on 3.14), type hints, `from __future__ import annotations`, small
  functions, module docstrings that explain *why*. Comments explain decisions, not syntax.
- TypeScript strict mode; API types in `types/api.ts` mirror the Pydantic schemas.
- Errors reach the user as `{"error": ..., "suggestions": [...]}` in plain language.
- Logs never contain document text (file names, sizes, timings, token counts only).
- Source files use **CRLF** line endings on this Windows checkout (`core.autocrlf=true`); keep
  edits consistent with the surrounding file.
- Commit messages: conventional style (`feat(scope): ...`, `fix(...)`, `docs(...)`), body explains
  why. Work happens on `main`; pushes go to both remotes (`origin`, `hamk`).

## Running models (practical limits)

- Development laptop: Ryzen 5 5500U, 16 GB RAM, **no GPU**. Recommended model **Qwen3.5-4B Q4_K_M**
  with `--reasoning-budget 0`. Reads ~22 tok/s, so the first question about a new selection takes
  minutes; follow-ups use the prompt cache.
- Only one `llama-server` can use port 8080. Running llama-server + backend + benchmark + LM Studio
  together has exhausted the 16 GB once; for long benchmark runs start only llama-server and the
  benchmark CLI. Interrupted runs continue with `run.py run --resume <run-id>`.
- Gemma-4-E4B writes its reasoning into the answer when thinking is disabled; see the README's
  evaluation report before choosing it.
